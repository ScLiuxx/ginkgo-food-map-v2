## 2026-11-23：小程序获赞详情、上游合并与剩余能力迁移

- 上游合并：新增 `upstream` 指向 `kanno111/foodmap`，拉取后本分支落后 47 个提交；`git merge-tree` 仅报告三份文档冲突，代码无冲突。上游将后端包名迁移为 `com.foodmap`、下线食堂窗口体系、新增推荐榜与使用统计等能力；小程序按合并后的服务端契约完成同步适配。
- 消息中心补齐获赞详情：`GET /api/me/received-likes/{id}/target` 按点赞关系编号重新鉴权读取被赞点评或回复，校验当前用户、通知类型、点评回指、餐厅回指和作者身份；详情展示原文并可进入所在店铺，源内容失效沿用“内容已失效或不可访问”。至此消息中心公告、回复、获赞、关注与审核结果均可在小程序内打开，不再保留“请在网页端查看”的获赞提示。
- 窗口体系下线：小程序删除窗口列表、独立窗口详情、窗口点评、窗口相册及全部 `windowId` 分支；食堂直接以自身 `restaurantId` 展示资料、收藏、点评与互动，消息回复、本人点评、公开主页和分享路径统一按店铺编号跳转。窗口推荐率字段随接口一并移除。
- 点评契约迁移：推荐态度改为 `RECOMMENDED`、`NEUTRAL`、`NOT_RECOMMENDED` 三态，正文去首尾空白后按码点计 1–500，四维评分 0–10、步进 0.5；发布统一走 `/api/restaurants/{id}/reviews`，回执读取 `reviewId`、`restaurantId`、`replayed` 并回指同一店铺，幂等指纹包含推荐态度与正文。详情、写点评、本人内容、公开主页和消息定位均按三态展示推荐徽标。
- 找店与选店：目录接口新增 `hasReviews` 筛选；随机选店改调 `POST /api/restaurant-picker/candidates`，由服务端在完整合格集合上不放回抽取，客户端以 `excludeIds` 维护本轮已看店铺并排除同批候选，“上一家”以 `checkIds` 复核。范围只提供清水河、沙河与我的位置，选择我的位置时才申请 GCJ-02 定位；预算、评分、分类和用餐方式交给服务端筛选。
- 新增近期推荐榜页：读取 `/api/restaurant-rankings`，按校区与周／月切换，READY、PREPARING、UNAVAILABLE 三态原样呈现，不重排、不补店，也不把无快照降级为空榜。
- 账号与资料：登录同时接受用户名、注册邮箱和纯数字学号，学号由服务端补全学校邮箱；新增头像上传与公开读取，使用微信头像选择器取得正方形图片，以 `AVATAR` 用途压缩到 512×512、300KiB 后调用 `PUT /api/me/avatar` 绑定，成功后记录本地版本号绕过图片缓存，加载失败或 204 回退用户名首字。
- 投稿附带点评：仅新店普通餐厅可附带评分、推荐态度和 1–500 字正文，随投稿一起审核，通过后以本人身份发布；附带点评图片暂未接入。投稿与纠错的字段白名单、内容指纹和 `clientRequestId` 规则不变。
- 地图页站内关键词搜索保留：结果由目录接口读取并以列表覆盖地图，不受当前视野限制，可继续加载并进入详情；高德外部地点依赖网页端 JS SDK 与密钥代理，不在小程序直接暴露。
- 详情页保留本人点评删除、点评照片墙和高德位置打开：删除需二次确认，204 后整页重读评分与点评；照片墙汇总当前已加载点评图片并统一预览；店铺带完整坐标时调用 `wx.openLocation`，食堂同样按自身坐标处理。
- 检查修复：成长规则与投稿页移除“窗口”残留文案；点评回复增加作者头像，204 或加载失败时仅回退该条回复的用户名首字。
- 静态核对：`app.json` 页面文件齐全，WXML 事件处理函数均有对应实现，页面跳转目标均已注册（登录页动态路由除外），全部 JSON 可解析且 WXML 标签闭合检查通过。
- 文档同步：小程序已覆盖高级筛选、服务端随机选店、近期推荐榜、餐厅与食堂直接点评、头像、学号登录和投稿附带点评；剩余缺口为目录页距离筛选、高德外部地点搜索与投稿点评图片，贡献榜、独立照片墙页面与管理端保持未开放。
