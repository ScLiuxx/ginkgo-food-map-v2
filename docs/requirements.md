# 泥电美食地图总需求

本文定义项目统一的最新产品需求，不记录更改历史、开发过程、提交或部署状态。需求不代表功能已经实现：当前能力见[功能说明](features.md)，接口协议见[API文档](api.md)，实施和验证记录见[开发记录](development.md)。

## 1. 产品定位与范围

面向电子科技大学学生，提供校园及周边餐饮发现、真实体验点评和商户资料共建。商户资料由用户提交，项目负责人或其他具有权限的管理员审核通过后公开生效。

核心流程：搜索或地图找店 → 查看资料与点评 → 登录分享真实体验；发现新商户或资料错误时，提交新增、补充或修改申请，由管理员审核。

- 商户包括普通餐厅和食堂，食堂下设独立窗口。首页展示普通餐厅和食堂，窗口在所属食堂内展示。
- 首页以单列商户目录为主，不设置独立点评信息流。
- 提供评分、推荐判断、照片、回复、地图、搜索、随机选店与分享。
- 不提供订单、支付、配送履约、商业推广位或商家经营后台。
- 不使用杯型评级、杯型筛选或杯型榜；管理员不能直接填写商户综合分。

## 2. 角色与权限

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 阅读公开商户、地图、点评、照片和评分说明 | 允许 | 允许 | 允许 |
| 提交商户新增、补充和修改申请 | 不允许 | 允许 | 允许 |
| 审核商户申请并使其公开生效 | 不允许 | 不允许 | 按审核权限允许 |
| 直接覆盖公开商户资料 | 不允许 | 不允许 | 按管理权限处理 |
| 发布点评、上传点评照片、回复 | 不允许 | 允许 | 允许 |
| 删除点评 | 不允许 | 仅本人内容 | 按管理权限处理 |
| 商户上下架、删除和恢复 | 不允许 | 不直接操作公开状态 | 按管理权限处理 |
| 导入、完整导出、恢复、永久清理 | 不允许 | 不允许 | 按独立管理权限处理 |
| 授予权限、修改系统配置 | 不允许 | 不允许 | 按独立授权处理 |

服务端从认证上下文确定账号与角色，不信任客户端自报的作者、创建者、审核者或权限。停用账号和失效凭证不能写入。管理员不能伪造他人作者身份、代填评分或借审核直接修改统计结果。

## 3. 账号与登录

- **AUTH-01 注册**：使用允许的校园邮箱验证码注册；页面后缀固定为`@std.uestc.edu.cn`，服务端独立校验域名。用户名2–24个字符，允许中文、英文字母、数字和下划线，去首尾空白，区分大小写且唯一。密码4–32位ASCII字母、数字或英文符号，不含空格和中文，不强制组合。注册成功自动登录。
- **AUTH-02 登录与退出**：用户名密码登录，密码安全哈希保存；服务端检查账号状态与权限。退出当前会话后不能继续使用该会话访问受保护接口。
- **AUTH-05 管理账号分流**：普通账号与管理账号共用登录表单，后端返回真实角色，管理账号登录后仅显示管理工作台，不暴露前台操作导航；日常浏览、投稿和点评使用另一个普通账号。普通账号不显示管理员登录入口，也不能绕过服务端管理权限校验。工作台提供退出以更换账号；首个管理账号须受控授权，不内置通用默认密码。
- **AUTH-03 登录保持**：使用Bearer凭证与独立会话，默认7天到期，不自动续期；重新打开恢复有效登录，多标签页同步退出和账号切换，不保存密码。
- **AUTH-04 找回密码**：邮箱验证码设置新密码；验证码用途隔离、限流、一次性消费。改密后全部旧凭证失效，返回登录页只预填用户名，密码留空，由用户主动登录；不得因此解除账号停用。
- 表单使用明确标签，不在账号输入框使用占位文字；错误显示在相应字段下方，密码可切换显示与隐藏。
- 访客触发写入操作时引导登录，登录后返回安全的站内页面，由用户继续操作，不自动代为提交。

## 4. 商户目录与详情

### REST-01：浏览、搜索、筛选和排序

- 商户行显示名称、分类、人均、地址、业务标签、评分、点评条数及可用的用户距离。未知价格显示待补，无点评显示暂无评分，不将未知值补成0或编造距离。
- 搜索名称、地址、分类和标签，去首尾空白，支持中文及常见大小写差异。空关键词读取默认列表。
- 筛选、计数和排序在完整匹配集合上执行，再分页；默认每页8条，接口单页最多100条。
- 美食品类采用横向导航及选中下划线；食堂是场所类型，不与火锅等美食品类混用。
- 主排序互斥单选，选中态、请求参数和结果顺序一致：

| 选项 | 排序规则 |
| --- | --- |
| 综合排序 | 默认选项，综合评分降序，未评分排后，同分按名称和ID稳定排序 |
| 距离最近 | 点击立即选中，取得用户位置后按直线距离升序，同距离按名称和ID稳定排序 |
| 好评优先 | 推荐比例降序，同率按计分人数降序，再按名称和ID稳定排序，未评分排后 |

- 页面不提供人均排序按钮、校区选择器或距校区多少米的筛选项。
- 提供隐藏停业餐厅，以及更多筛选中的人均上限、餐厅类型、用餐方式。人均可选20/30/50/100元或不限，包含边界；估值参与筛选，未知价格仅在启用价格条件时排除。
- 高级筛选使用独立草稿，确认才应用、取消丢弃修改、重置等待确认，不重置其他独立条件；显示已应用条件及可移除标签。
- 条件变化回第一页，旧请求不能覆盖新条件；翻页返回结果区，浏览器后退恢复阅读位置。
- 详情可直接访问、刷新与分享，显示资料、四维均分、综合分、推荐率、计分人数、点评条数、照片与讨论；点评分页不能改变全店统计。
- 删除或尚未通过审核的商户不得通过公开列表、搜索、详情或地图泄露。

### REST-02：用户提交与管理员审核

用户可提交新商户，或对已有商户补充、纠错。审核通过前，申请不作为正式商户公开，也不覆盖已有公开资料；通过后才生效。不通过的申请不得写入公开资料。审核账号、对象、时间及结果应可追溯。

| 资料 | 要求 |
| --- | --- |
| 名称 | 去首尾空白后1–40个Unicode字符；允许同名分店，不按名称直接覆盖 |
| 美食品类 | 受控分类字典，服务端检查存在且可用 |
| 餐厅类型 | 普通餐厅或食堂，与美食品类分开 |
| 堂食、外卖 | 两个独立属性，可同时支持；未知不等于不支持 |
| 人均 | 可选整数元1–5000，区分填报与估值；未知为NULL，不用0代替 |
| 地址 | 最多80个Unicode字符，允许未知，不把空值标记当正文 |
| 位置 | 用户在商户名称框输入店名，通过高德搜索并选择门店，自动填写店名、地址与位置，不开放经纬度输入；已有位置未改动时允许核对后保留。坐标使用GCJ-02，纬度3–54、经度73–136，最多6位小数，成对提交并确认 |
| 标签 | 去空白、去重，最多8项，总长度最多80个Unicode字符 |
| 经营状态 | 正常经营或停业，与审核、删除状态独立 |
| 账号和时间 | 服务端确定，不允许客户端指定创建者、审核者或伪造时间 |

美食品类包括火锅、川菜、小吃、快餐、烧烤、甜品、冒菜、面馆、麻辣烫、粥粉面、轻食、其他；食堂类型与相应分类的管理须保持一致。

- 普通用户不能因创建过商户而绕过审核直接修改公开资料，也不能提交综合分、推荐率或点评数量。
- 位置不得以默认校园坐标代替；待定位仅用于受控导入或明确的草稿，不进入地图。用户新增商户公开生效前必须确认真实位置。
- 审核及生效必须检查当前权限、目标与状态，公开资料及整组标签同事务保存，失败不能部分生效；不要求餐厅编辑版本号，删除记录不能由普通保存请求复活。
- 申请明确区分新建与纠错，审核后仍保留原类型。新建通过创建新商户并记录其ID，纠错沿用原ID；保留用户原始申请，通过后另存管理员修订结果及纠错前资料。待审无审核结果，通过需有审核人/时间及生效资料，驳回需有审核人/时间和非空原因；原提交重试不因新商户ID生成而被误判为不同目标。

### REST-03：经营状态、删除与恢复

- 停业商户保留资料与点评，允许继续发表真实经历；停业不等同于删除。
- 管理员删除商户采用软删除，确认关联影响并记录操作者、时间和原因；公开入口同步隐藏其仍存在的点评、回复和图片。
- 恢复仅由有权管理员执行，只重新展示仍有效的关联内容，不恢复已物理删除的点评及关联内容。
- 重复删除、恢复和并发操作有稳定结果，不重复计分或越权更改状态。

## 5. 食堂与窗口

- 窗口有独立ID、详情、参考价格、经营状态、点评、评分及照片，不能借用父食堂ID冒充窗口身份。
- 食堂内可按楼层和美食品类筛选窗口；首页不额外拆成三套主入口。
- 发布食堂点评须选择具体窗口，从窗口详情进入时锁定目标；服务端也检查目标，不能只依赖页面选择。
- 食堂整体评分按营业、未删除且已有评分的窗口等权平均；真实零分参与，无评分及关闭窗口跳过，无可计分窗口则显示暂无评分。
- 食堂整体点评不计入窗口统计或窗口汇总分，不同窗口的点评与评分不能混用。
- 窗口资料维护遵循商户提交审核规则；堂食和外卖在商户或食堂层面明确记录，不从名称、标签或缺失资料推断。

## 6. 地图、定位与地点搜索

### MAP-01：地图与列表

- 使用高德JS API 2.0，默认成都区域视野；支持移动、缩放、总览、商户选择和详情联动。导航跳转高德目的地，由高德处理起点和路线，不开发站内路线规划。
- 地图与列表采用同一业务筛选口径；地图按当前视口独立查询，每次最多100个餐厅点位。真实匹配数与返回数分开，超限提示放大地图，不把截断结果称作全部。
- 移动或缩放结束后约300毫秒合并查询，迟到结果不能覆盖新视野；列表仍按完整匹配数量分页。
- 待定位或缺坐标的商户不绘制点位。点位展示真实评分和经营状态，悬停、键盘聚焦及点击有可辨识反馈，手机支持点击摘要。
- 地图加载、定位或区域更新失败时，保留本站搜索、列表和详情能力，不将错误当成无结果。

### 用户位置与距离排序

- 点击“距离最近”才申请一次定位，不在页面打开时自动申请，不持续跟踪；点击即选中，已有位置直接复用。
- 等待用户授权不提前超时，设备取位置与坐标转换分别限制等待；失败显示具体原因，允许重试或切换其他排序。
- 浏览器GPS位置转换为GCJ-02后计算，不混用或重复转换坐标。用户位置仅保留在当前浏览会话，不绑定账号或写入数据库。
- 以用户原点对全部匹配商户排序后分页，不只重排当前页；显示球面直线距离，不声称是步行或驾车距离。
- 无位置时不展示虚构距离、不以校区代替用户。距离选项等待定位，不展示其他排序冒充距离结果；拒绝定位仍可使用其他功能。
- 位置更新不能覆盖用户后来切换的排序；按钮选中态、查询参数和实际顺序保持一致。

### MAP-02：地点检索与位置确认

- 本站商户与外部候选地点明确分组、独立分页；外部地点不冒充本站评分、照片或点评。
- 地图关键词搜索不受当前视口限制，默认优先理解成都范围；请求防抖并保护结果顺序。
- 多个候选展示名称和地址，供用户辨认分店；地址解析仅辅助定位，不将路名自动变为商户名。
- 商户申请支持确认地址、坐标与地图点位，点选可预览、确认、取消，不丢失其他资料。服务不可用时允许受控手填，不把失败结果当有效位置。
- 外部地图信息须遵守接口授权及保存范围；地点搜索或选点不能自动入库或绕过管理员审核。

## 7. 点评、评分和回复

### REVIEW-01：发布与读取

- 登录且账号可用的用户可对公开有效餐厅或窗口发表真实经历，作者取自账号，不允许匿名或另填昵称。
- 味道、性价比、服务、环境四维全部必填；存储0–10分，步长0.5。详情和发布界面采用五星半星展示或输入，按明确比例换算，不修改计分口径。
- 推荐与不推荐独立选择，不由高分推断；正文为纯文本，去首尾空白后5–500个Unicode字符。
- 同账号可因不同经历多次评价同店，不设一人一店唯一约束，不新增每日限次或冷却门槛。
- 主列表按账号展示最新点评，历史按需读取并保留各自照片、回复。分页和历史展开不改变全店评分。
- 点评直接发布，不纳入商户资料前置审核；作者或管理员可事后删除。失败保留合理草稿，账号切换后不自动代发。
- 同次提交重试防重，网络超时不能重复创建、重复计分或将未落库结果显示为成功。

### SCORE-01：计分口径

| 指标 | 计算规则 |
| --- | --- |
| 单条综合分 | 四维算术平均，HALF_UP保留两位小数 |
| 代表点评 | 每账号、每个评价目标取最新有效点评，以服务端时间和ID确定 |
| 商户综合分 | 所有代表点评的单条综合分等权平均 |
| 四维均分 | 分别对代表点评的对应维度求平均 |
| 推荐率 | 代表点评中的推荐人数 ÷ 计分参与人数 |
| 点评条数 | 所有保留的有效点评数量，包含同账号历史点评 |
| 计分人数 | 有代表点评的独立账号数，不随历史条数增长 |
| 无评分 | 综合分、四维和推荐率为NULL，计数为0，显示暂无评分 |
| 真实0分 | 正常参与统计，不能当缺失值 |

单条总分先舍入，再求商户均分；不能用当前点评页或照片墙子集计算统计。删除最新点评后，上一条有效点评重新参与；无其他点评则移除该账号贡献。停用账号不自动追溯删除其正常历史内容。

例如四维8/8/8/7.5得到7.88；一人两次评分8、6，另一人评分9，对应3条点评、2人计分、均分7.50。发布、删除、统计和推荐率采用同一有效集合，管理员不能直接改分。

**SCORE-02 评分说明**：解释四维含义、计算顺序、人数与条数、推荐率与综合分的区别及样本较少的局限。规范要求真实体验，禁止刷分、人身攻击、广告及泄露隐私，不暗示学校官方认证。

### REVIEW-03：删除点评

- 作者可删除本人点评，有权管理员可处理点评；操作前确认，服务端检查权限和状态。
- 点评、回复、照片关联与统计一致处理；媒体标为待清理，OSS删除失败可重试。
- 点评物理删除，不提供点评回收站或恢复；商户恢复不能找回已删除点评。
- 发布回执在点评删除后仍阻止同次请求重放复活内容；重复删除不重复扣分。

### COMMENT-01：单层回复

- 登录用户可回复公开有效点评，正文1–200个Unicode字符、纯文本，作者与时间由服务端确定。
- 回复不计分、不改变点评创建时间；稳定排序和分页，不静默截断合法内容。
- 支持按钮发送，桌面回车发送须避开输入法组合输入；父商户或点评不可用时不能新增或绕过父状态读取。
- 不提供楼中楼或独立回复编辑；点评删除时一并删除回复。

## 8. FILE-01：点评图片

- 每条点评最多5张，支持文件选择、桌面拖拽、发布前预览与移除；详情提供照片墙及大图。
- 服务端独立验证真实格式、解码、像素、大小和归属；接受JPEG、PNG、WebP，不接受SVG或伪装文件。最终最长边不超过1200像素、单张不超过300KiB，清除不必要的EXIF位置等元数据。
- 图片本体存阿里云OSS，数据库保存元数据与关联；不将base64塞入正文，不依赖单台设备的本地缓存。
- 临时文件有明确有效期，只允许上传者绑定；发布时检查数量、归属、状态和期限，与点评关联一致保存。
- 图片失败明确提供重试或移除，不静默降为文字发布成功；用户明确移除后才可只发文字。
- 正式读取遵循点评及商户可见性，不接受任意外链、路径或他人文件ID替代上传。
- 取消、过期与删评后的对象可重试清理，不能删除仍被有效内容引用的对象。商户软删除只限制可见性，不提前清理其可恢复照片。

## 9. 分享与管理

- **SHARE-01**：详情可复制名称、地址及稳定详情链接；剪贴板或原生分享不可用时提供手动复制文本。分享不包含认证信息、邮箱或用户精确位置；删除商户的旧链接不泄露管理资料。
- **ADMIN-01**：管理员独立授权，提供申请审核、公开商户资料管理、商户回收站及点评处理。操作账号、对象、结果和时间可追溯，普通用户不能读取管理元数据。首次管理员经受控运维授权，不能自助提权或共用管理密码。
- **ADMIN-02**：永久清理是独立高权限操作，执行前预览范围与照片影响，具备备份、失败明细和重复执行保护；不误删新数据或有效图片引用。

## 10. 导入、导出与恢复

- **IMPORT-01**：管理员预览CSV/TSV等资料，验证字段、坐标、分店关联、来源与重复记录，确认后按批次执行。预览零写入，失败有逐行原因，重复确认不多导；外部资料不伪造成本站真实点评、价格或图片。
- 缺分、未知推荐、无效日期和不明作者不静默补值；正式点评须满足账号归属与计分约束，昵称、设备ID或同名店铺不自动获得本站归属。
- **MIGRATE-01**：受控迁移具有来源快照、旧新ID映射、引用核对、缺失媒体报告及回退方案。坐标系明确，缺位置不补校园中心，缺分不补模拟点评。
- **BACKUP-01**：业务导出明确格式、时间、范围、数量和媒体清单，不含密码哈希、JWT、验证码、密钥或会话；业务导出不等同于系统完整备份。
- 完整恢复配套数据库与媒体备份，在隔离环境核对数量、引用、权限和统计；恢复先预览冲突，不默认覆盖生产数据。程序发布与回滚不能覆盖用户内容。

## 12. 数据一致性、安全与工程约束

- **SYNC-01**：服务端和MySQL是共享业务数据的权威来源；写入成功后刷新相关资料，其他设备重新打开或刷新可读一致结果，不把本地草稿或失败请求当作已发布。
- 写入默认认证，公开只读按方法与路径显式放行；身份、所有权、审核权限、文件归属和资源状态均由服务端检查。
- 正文、标签及导入内容不执行用户HTML；密码、验证码、JWT、私钥、SMTP及地图服务端凭据不进入Git、公开响应或日志。普通页面不暴露邮箱和管理内部信息。
- 公开读取检查父商户、点评及媒体可见性，不能靠前端隐藏或长期缓存绕过删除与权限。
- 发布、审核生效、绑定和导入确认需防重或可查询结果；事务失败不留下半更新统计。云存储请求与数据库事务分离，失败可重试或补偿。
- 评分统计可从有效点评重建；目录不逐条查点评或回传全库。列表、点评、回复、点位及文件有数量或容量上限，图片按需加载。
- 使用Java 21、Spring Boot 4、MySQL、Redis、Flyway、Spring Security及Vue 3、TypeScript、Vite、Pinia，保持按业务模块分层的模块化单体。
- 每个模块只访问自己的Mapper/表，跨模块通过公开应用服务或事件；评分统计归restaurant模块，review通过协作接口更新。Controller不承担核心规则，Entity不直接作为接口输入输出。
- 数据库变化使用新增Flyway迁移，不修改已执行脚本。实际表结构见[餐厅表说明](architecture/restaurant-schema.md)和[点评及媒体表说明](architecture/review-schema.md)。
- 部署使用HTTPS及受控配置，业务数据和媒体独立于发布目录；备份恢复、回滚和健康检查有明确流程，不能以版本更新删除新用户数据。
- 性能结论记录环境、数据量、并发、缓存状态及错误率，不承诺未经实测的容量或响应时间。

## 13. 核心验收要求

1. 访客可阅读公开商户；待审核、已删除及管理私有资料不能被直接请求泄露。
2. 普通用户提交新增或修改后，审核通过前公开资料不变；越权审核、伪造操作者、重复生效被拒绝。
3. 新商户无虚构点评、价格和评分，未知类型或用餐能力不默认描述为已核实。
4. 名称、地址、金额、标签、位置、评分、图片、正文均经服务端校验，失败不部分保存。
5. 距离按钮点击即选中，已有位置不重复申请；定位后的列表、参数、总数与跨页顺序一致，拒绝仍可用其他功能。
6. 地图最多100个点，计数真实，恰好100不误报超限，列表分页不因点位截断丢失。
7. 同人多评只取最新有效代表，0分有效，条数与人数明确，删除或重试不重复计分。
8. 餐厅与窗口目标独立，服务端拒绝混用父食堂和窗口ID，食堂汇总遵循有效窗口等权规则。
9. 图片跨设备可读，越权及超量被拒绝；删评、商户隐藏和恢复保持可见性与清理一致。
10. 恢复商户不复活已删除点评，点评不提供恢复；失效账号和会话不能继续写入。
11. 导入预览零写入、确认防重，恢复核对数据、媒体与评分；部署及回滚不覆盖用户内容。
12. 单元、接口、真实MySQL、必要的并发和浏览器测试覆盖主要行为；模拟定位、邮件、存储与真实外部能力验收分开记录，跳过不计通过。
