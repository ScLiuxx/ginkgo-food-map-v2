# 泥电美食地图功能说明

社区页面（2026-11-07）：按确认示意图将“我的”替换为独立个人中心，以用户名标识身份，提供我的点评、我的收藏、我的投稿/纠错及账号设置四个入口；不提供用户头像、最近浏览、私信或等级称号。个人中心、成长详情和本人主页已读取真实经验及数字等级，未接通的互动人数显示“—”，读取失败明确提示重试，不伪装成零经验。公开主页要求登录，已展示被查看者的用户名、简介、数字等级、当前获赞总数及按店分组的最新点评与历史；不显示邮箱、经验明细或投稿记录。店铺收藏、关注与粉丝名单已接入，不用本人的资料或本地假数据填充。设置页可查看真实脱敏绑定邮箱、编辑或清空个人简介，并进入现有密码重置及真实退出登录；收藏公开设置已接入，关注与粉丝名单隐私开关已接入。

个人简介：在“我的 → 账号设置”编辑，最多100字（表情按Unicode码点计数），保存后本人个人中心和主页同步展示，刷新后仍可读取。空白内容可清空简介，保存后直接生效；前后端检查常见微信、QQ、手机号及网址形式，基础识别不代表完整内容审核。读取失败可重试，保存失败保留本次草稿；取消、退出或换号清除草稿，换号后旧请求不会覆盖新账号。用户名只读，不提供改名、换绑邮箱或头像上传；当前接口只供本人读取资料，尚未开放他人简介查询。接口见[本人资料](api.md#15-本人资料与简介)。

我的点评：登录后从“我的 → 我的点评”查看真实跨店点评，按店铺分页，每家店默认展示最新有效点评，可查看历史、照片大图及回复，也可进入店铺详情。停业店铺仍可读，已删除店铺不进入列表及计数。删除本人当前或历史点评需二次确认，失败保留确认框供重试；成功返回第一页，最后一条删除后移除该店分组，普通删评不扣已获经验。读取失败和真实空列表分开显示，退出或换号立即清除旧正文。同样的按店分组与历史展开已接入登录可见的公开个人主页，访问他人主页不会获得他人点评删除权限。

我的投稿 / 纠错：登录后查看自己提交的新店和资料纠错记录，按提交时间从新到旧分页，可筛选待审核、已通过、已驳回。点击详情查看原提交内容、附图、审核时间、实际通过的内容或驳回原因；原投稿与管理员修订分别展示。关联店铺被删除后，申请仍保留，但不再提供可用店铺跳转；停业店铺仍可进入。记录和原申请附图仅本人及有权管理员可读，列表、详情及单图失败可分别重试，退出或换号清除旧内容及图片预览。修改待审申请、撤回和驳回重提尚未开放，审核通过已计入成长经验；通过和驳回会向原提交人发送系统通知。

消息与互动页面：入口现为“收到的赞 / 评论 / 新增关注”，系统通知保留单一会话；系统会话已显示真实审核通知摘要与未读数；进入系统分类分页查看新店/纠错的通过结果及驳回原因，点开一条仅标记该条已读并打开本人申请，首页及系统分类可一键全部已读。只浏览列表不清未读，失败可重试，退出或换号清除旧内容；原申请失效时提示“内容已失效或不可访问”。评论分类已接入：别人回复你的点评时逐条提醒，自己回复不通知，重复提交不重复提醒；通知不存正文，点开后显示原点评和本条回复，历史点评和后续分页回复也能直接找到。评论与系统通知分别统计未读，分类全部已读互不影响，首页处理全部。点评、回复或店铺已删除时保留通知，只显示内容失效；停业店铺仍可读。收到的赞已接通：点评和回复首次获赞逐条提醒，取消后原提醒保留，重新点赞不重复提醒；与系统/评论分别统计未读及全部已读。新增关注已接入真实分类、未读及已读后主页跳转；公告和消息删除尚未开放。点评、回复取消用户头像，作者用户名可进入个人主页（游客先登录）。点评与回复可点赞或取消，显示真实计数和本人状态，不允许自赞；本人页面显示有效点评和回复当前获赞合计，内容删除后扣除对应点赞。店铺收藏已接入，单独删除回复仍待开放；举报可打开明确标识未开放的弹窗，不提交或保存，原因分类也未预设为正式规则。账号处罚、受限登录和申诉仍待后续实现，不为没有处罚的用户增加申诉入口。各规则组的接入范围见[社区前端状态](plans/community-frontend.md)。

成长等级：后端已接入每用户每店首次成功发布点评默认获得5经验，重复请求、同店再评和删评重发不重复领奖，普通本人删评保留经验。前端通过[本人成长接口](api.md#14-本人成长摘要)查询累计经验、数字等级及下一等级进度，默认门槛为0/100/400/1000，升级不消耗经验；尚未获得经验时查询不会创建账户。发奖与点评、图片及评分统计一起提交，失败整体回滚。新店投稿审核通过默认获得20经验；纠错通过默认获得10经验，同一人对同一家店仅奖励一次，后续仍可正常纠错。奖励属于原提交者，管理员直接维护、待审、驳回及重复审核均不计奖；商户资料、相册、审核结果和经验一起提交或回滚。已通过的历史申请不补发经验。重新进入个人中心或成长详情即可读取最新经验与等级；当前没有后台推送自动刷新。点评获赞按暂定每次+1、同一人每日最多为同一作者贡献一次、作者每日最多+5，超限仍可点赞；取消及普通删除不扣回已发经验，回复获赞不计奖。点评作者数字等级、公开主页和默认/时间双排序已接入；代码验证与运行状态见[开发记录](development.md)，表结构见[成长经验表](architecture/mysql-schema.md#growth-schema)。

商户搜索：支持中文组合词和单汉字搜索；组合词默认相关度，单字默认综合评分，用户选择的业务排序优先。筛选、计数、排序和分页在完整匹配集合上执行，列表与地图共用规则。评分及好评率按已确认的一位小数精度排序，未知值保持未知，关键词最多访问前10000条。

同步与故障保护：业务资料保存在MySQL，修改后通过Outbox更新ES。查询回查当前资料和版本，故障、同步积压或资料变化时整次使用基础搜索；查询熔断在连续故障期间跳过ES，并通过少量真实请求探测恢复。页面保留实际匹配和排序提示。具体语义见[API](api.md#621-正式搜索与简单降级契约2026-11-05)。

验收与运行：ES第一版核心功能已通过用户人工验收；本地http://localhost:5173已显式开启ES查询及增量同步，默认共享配置仍关闭，尚未部署线上。结构和后续事项见[搜索计划](plans/elasticsearch-search.md)，当前版本的速度、词法目标命中及限制见[最终评测](history/elasticsearch-final-benchmark-2026-11-05.md)，历史空间实验见[文档导航](README.md#历史追溯)。

管理导航统一（2026-11-04）：商户审核、商户管理及新增/编辑页面使用同一左侧导航，统一审核清单、店铺、点评与历史图标，以及浅橙选中态、禁用颜色和“后续”标记；审核数量来自真实申请统计。手机端统一为带图标的横向导航。

管理员类型与用餐方式维护（2026-11-04）：商户管理的新增、修改页面现可编辑“餐厅类型”“支持堂食”“支持外卖”，保存后真实写入正式商户并公开。堂食和外卖分别支持未知、支持、不支持，可随时改回未知。选择食堂自动清空美食分类，切回普通餐厅需重新选分类；已关联窗口的食堂（包括已删除窗口）不能直接改为普通餐厅，失败保留草稿。后端已有数据列无需新迁移，保存及失败回滚同时维护搜索投影版本。管理员直接上传商户相册仍待接入，不属于本次字段开放。

管理端表单与分页更新（2026-11-04）：新增和修改店铺直接复用用户“补充 / 纠错”页面及高德门店搜索，选择分店后自动填写名称、地址和位置，不再手输坐标；管理员点击创建或保存直接生效，不生成待审申请。编辑读取管理员授权资料，并展示已有公开相册。直接保存暂不支持改餐厅类型、堂食/外卖或新增图片，对应字段保持只读，用户投稿流程仍支持原有能力。商户列表提供数字页码、首页/末页、10/20/50/100条每页和指定页跳转；翻页由后端完整分页，调整每页数量回到第一页，未点击查询的筛选草稿不影响当前翻页。

管理端商户直接维护（2026-11-04）：从管理工作台的“商户管理”进入，支持真实店铺查询、分类筛选、分页、新增、编辑及二次确认软删除。保存后直接公开生效并返回管理端；删除后保留店铺ID，可在“按ID管理 / 恢复店铺”查询删除资料并确认恢复。加载和写入失败保留明确提示，切换账号后停止原账号操作。现阶段复用已有接口：公开列表包含停业店铺但不包含已删除记录，尚无可分页的回收站；新建为普通餐厅，直接维护表单不支持切换餐厅类型或修改堂食/外卖，已有值保留。位置使用现有GCJ-02坐标输入与确认；正式相册不在此次维护范围。管理页直达/刷新等待首次路由完成后再执行身份跳转，避免误回审核页。

本地学校食堂资料已核对12条：清水河校区的朝阳、西北、银桦、芙蓉、紫荆、学子、家园、桃园、科创及“一食堂”聚合地点，沙河校区的阳光、桂苑。这些记录按食堂类型展示并标记支持堂食；食堂类型与美食分类独立。“一食堂”可能与具体餐厅重叠，暂未合并；思源、青创、风华、万友尚未找到明确对应记录，因此目前并未收齐学校全部食堂。价格、外卖服务及位置仍沿用已有资料，窗口明细尚未录入。

普通餐厅采用九个一级分类：小吃快餐、中餐地方菜、火锅串串、烧烤烤肉、香锅烤鱼、国际美食、甜品烘焙、饮品、其他美食。每家普通餐厅按主营业务选择一个分类，不设置二级分类。食堂整体不设美食分类，显示“食堂”；窗口保留自己的美食品类，未录入时保持未知。首页“全部美食”包含食堂，具体美食品类不包含食堂；在“更多筛选”的餐厅类型中选择食堂即可单独查看。投稿、纠错和审核选择食堂后清空分类并停止提供分类选择，切回普通餐厅必须重新选择；旧审核快照保留原内容。旧细类保留用于历史资料解释，不再提供新建选择。存量普通餐厅资料结合原始类型和明确店名证据整理，证据不足保留原分类，混合经营或疑似非餐饮名称列入待核，不据此宣称已经核实经营信息。

商户审核：管理员可修订投稿资料并真实通过或驳回。新店通过后生成正式商户，纠错更新原商户；餐厅类型（普通餐厅/食堂）和堂食、外卖情况随审核真实生效，支持“未知、支持、不支持”。原始投稿保留，另存最终通过资料、纠错前资料、审核人及时间。重复操作不会重复建店，也不会覆盖首次审核结果。已有窗口关联的食堂不能直接改为普通餐厅。后端已接通正式相册：首次通过时附图一起发布，纠错图片追加到末尾，无图保留旧相册，第一张为默认封面；历史已通过图片不自动公开。

统一登录与管理员入口：所有账号使用`/login`登录，普通用户进入首页或安全的原页面，服务端返回`ROLE_ADMIN`的管理账号直接进入`/admin/reviews`。不再展示独立管理员登录表单或入口，旧`/admin/login`兼容跳转统一登录。管理账号只显示工作台，手动访问首页、地图、账号页等也返回工作台；后台品牌链接留在管理端，不提供“返回前台”，日常浏览和点评需退出后换普通账号。工作台挂载前调用`GET /api/admin/me`，由后端核验JWT、Redis会话和数据库最新管理员角色；普通账号返回403，过期会话返回401，依赖故障保留凭证供重试。页头显示真实用户名并提供退出，失败可重试。刷新及跨标签页账号变更先验证身份，不提前挂载其他账号界面。密码不持久化，登录完成或离开表单后清空。前后台共用一个会话，切换影响同一浏览器其他标签页。首个管理账号须单独授权，没有默认管理员密码或公开提权入口；工作台已接入真实申请查询、修订、通过和驳回。

管理端商户审核：管理员进入/admin/reviews可读取真实申请，支持状态筛选、商户名称或完整申请编号搜索、分页及状态计数。详情对差异加浅橙底纹与旧值删除线，可就地修正名称、分类、地址、坐标、人均、经营状态、位置确认和标签，底部常驻“审核通过并更新”“驳回”按钮。驳回先显示快捷原因浮层，点击原因才提交。勾选连续审核后，成功处理自动加载刷新后队列的下一条；取消勾选则保留处理详情。提交期间防重复操作，失败保留草稿，列表刷新失败与审核失败分别提示。已通过展示实际通过资料和审核前快照。已删除目标禁止通过，仍可驳回。图片继续通过管理员认证查看、放大及独立重试；商户管理、点评管理和操作记录页面暂未开放。

商户图片：补充/纠错与新店投稿页可点击正方形加号选择最多5张图片，支持JPEG、PNG、WebP，自动压缩后上传，提供预览、移除及失败重试。图片未传完或失败时不能提交申请。提交后与申请一起等待审核；首次通过后，后端将附图关联到正式相册，支持匿名分页和JPEG读取。驳回不公开图片，商户删除后停止公开，恢复后可读；重复审核不重复发布，任意图片或审核写入失败整体回滚。取消未提交图片的清理规则保持原样。

首页和详情写评支持文本及最多五张照片：登录后填写评分、推荐和正文，照片先完成上传再提交。成功显示点评编号；同内容失败重试保留文件ID和UUID。发布中冻结表单，登录失效时正文锁定可复制。暂不提供餐厅预测分数。

详情具备评分、点评卡片和图片等展示组件。详情页已接入公开点评列表：不登录也能按人翻页，每人显示最新点评，附历史条数和按选择顺序排列的照片，点击可看大图。列表分别显示评价人数和点评总条数；失败可重试，切换餐厅不混入旧请求结果。发布成功保留编号回执，点击完成或关闭回执后刷新第一页。历史点评已支持按需展开，每次5条，可加载更多，保留原记录的评分、时间、正文和照片；本人删评已开放，独立照片墙仍未开放。餐厅汇总评分、推荐率、四维和人数/条数已经接入。关闭成功回执后分别刷新点评第一页与餐厅统计，不卸载讨论面板；统计读取失败显示上次数据和独立重试入口，不重新发布。

点评默认只展示作者、评分、正文、照片及一行“回复 / 查看回复 / 历史点评”操作，移除重复的“评价依据”折叠块。点击“查看回复”才读取列表，每次10条，按时间从早到晚展示；点击“回复”才显示编辑框，支持1–200字纯文本、回车发送与Shift+回车换行，输入法选字不误发。同一时间只显示一个编辑框，取消或切换点评保留各自草稿。历史点评在桌面右侧面板、手机底部面板中按需读取，关闭后返回原位置，重开保留已读内容与草稿，历史照片和回复仍属于原点评。

游客可读，点击回复引导登录。发送失败保留文字和同次请求编号；成功后关闭编辑框、只刷新当前点评的回复区，保留历史面板和点评分页。发送成功但读取失败会单独提示，可只重试读取。切换账号会清空旧账号草稿，回复不影响评分。当前接口未提供回复总数，因此入口不显示未经读取的数量。

### 删除自己的点评

登录后仅在自己发布的最新、历史点评上出现“删除评价”。取消或按Escape不删除；确认后永久移除该条及其回复、照片关联，刷新点评第一页与餐厅统计。删历史不改变评分；删最新由上一条接替；删本人最后一条移除本人评分。失败在确认框内重试。照片立即停止公开访问，云端清理由后台重试；不支持恢复或管理员代删。

### 多次点评展示预览

首页页尾“多次点评展示预览”或`/previews/review-history`可以查看明确标注的示例。小王同店两次点评归在一张主卡内，最新点评在上方，旧点评默认收起，展开保留原回复；小李独立成卡。

初始示例为3条点评、2人、综合7.50分。可以切换当前计分记录，演示删除最新点评后的8.50分及重置。所有操作只影响预览页面，不写入数据库。当前后端协议见[点评接口](api.md#10-点评)。
