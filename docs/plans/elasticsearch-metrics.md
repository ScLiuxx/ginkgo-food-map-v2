# ES 检索指标建设计划

更新：2026-11-10。状态：受保护的采集端点、列表检索埋点、独立采集认证、Prometheus本地配置及Grafana检索/同步看板已实现；另有八条本地告警及规则测试。告警配置与阈值见[告警说明](../operations/search-alerts.md)，本地看板见[Grafana说明](../operations/grafana.md)。访问及启动见[Prometheus运行说明](../operations/prometheus.md)，现行指标口径见[检索指标](../operations/elasticsearch-metrics.md)和[同步指标](../operations/elasticsearch-sync-metrics.md)。

## 目标与范围

使用 Micrometer、Spring Boot Actuator、Prometheus 和 Grafana，观察首页列表检索的请求量、耗时、ES承担比例及降级情况，为后续优化建立基线。

查询指标覆盖 `/api/restaurants` 的无关键词浏览和关键词检索，另已增加Outbox同步存量、事件和耗时指标。不接入Logs、Trace，不覆盖地图独立检索和ES集群内部指标，不修改检索及降级行为。整体优化安排见[搜索实施计划](elasticsearch-search.md)。

## 首期指标

已覆盖请求量、总耗时、ES阶段耗时、数据来源、最终失败、降级原因、零结果及每阶段SDK调用次数。沿用既有共享熔断指标，不重复注册；列表与地图分开统计。QPS、比例和P50/P95/P99由后续Prometheus查询计算，具体口径统一见[检索指标说明](../operations/elasticsearch-metrics.md)。

## 实施步骤

1. **接入与埋点（已实现）**：核对现有依赖，接入Actuator及Prometheus Registry。在`RestaurantQueryService`记录请求结果、总耗时和降级，在`RestaurantSearchReader`记录ES读取阶段耗时，从现有熔断器读取状态。监控故障不得改变业务结果。
2. **验证口径**：通过隔离测试核对普通浏览、关键词、零结果、主动关闭ES、ES异常后SQL成功、SQL也失败及熔断恢复，确保无重复计数；用实际ES补充连接故障与恢复验证，不修改业务数据。
3. **采集与展示**：Prometheus本地每30秒采集的配置已实现，使用独立只读凭据；Grafana配置已实现，展示请求速率、ES承担比例、整体及ES阶段P95、降级率与原因、熔断状态。ES承担比例按成功请求来源计算，降级率按计划走ES的请求计算，主动关闭ES的SQL流量排除在分母外。
4. **本地告警**：新增采集失败、共享熔断持续打开、列表降级/最终失败比例和P95规则，每15秒评估；使用最低流量和持续时间过滤波动，离线规则测试验证主要边界。Prometheus页面查看规则与排查信息，Grafana看板顶部复用ALERTS展示已触发/等待计数及实例明细，尚未接入通知投递。
5. **同步观测**：定期汇总Outbox待处理/失败/到期/重试任务与最老等待，在实际消费处记录结果、重试、409、确认异常及耗时，并记录餐厅分组、合并任务数及Bulk请求/耗时/大小/文档结果/429。消费已改为提交后异步通知、固定200毫秒窗口、30秒定时兜底，批内按餐厅合并后Bulk写入，详见[同步说明](../operations/elasticsearch-sync-metrics.md)。Grafana增加同步专区，顶部接入积压、失败和快照/消费心跳陈旧三条告警；指标记录失败不得改变原消费语义。

## 资源与访问

- 关键Timer启用用于聚合P95的直方图，按实际耗时选择桶，避免为全部Timer开启大量桶。
- Prometheus初期保留7天，数据保留大小先设2～3GB；该限制不等同于进程总磁盘硬上限，预留WAL等空间。
- Grafana刷新间隔30～60秒。记录接入前后内存、CPU和查询耗时，不预先承诺容量或性能收益。
- Actuator按最小范围暴露采集端点，限定内部网络或受控认证访问，不整体放开管理端点。

## 验收与后续

- 指标可被Prometheus持续采集，看板能区分正常ES、主动SQL、故障降级和最终失败；零流量时不显示误导性比例。
- 测试核对计数、标签和计时边界；检查端点访问控制，并保留故障恢复及资源占用记录。
- 当前告警阈值仅为可复现的本地演练初始配置，不作为生产SLO；取得真实流量基线后再校准。通知投递、地图独立检索指标、完整数据对账及ES集群指标后续按需要接入。
