# 帮我选一家：业务规则与实施状态

更新：2026-11-13。实现来源分支：`feature/restaurant-picker`。前后端与详情返回已接通，验收结果由[开发记录](../development.md)维护；没有新增或调整表结构。

本文是本功能的业务规则主要来源。已实现接口见[API](../api.md#25-帮我选一家候选查询)，用户使用说明见[功能说明](../features.md#帮我选一家)。

## 已确认业务规则

### 进入与条件

- 使用“帮我选一家”弹窗，条件独立于首页，不继承首页搜索和筛选。
- 每次关闭后重新进入从条件选择开始，不记住上一轮选项。
- 所有条件均不预选，用户逐项选齐后点击抽取才展示餐厅。
- “不限”是用户主动选择的有效值，必须与“尚未选择”区分。

| 条件 | 可选内容 | 规则 |
| --- | --- | --- |
| 范围 | 清水河附近、沙河附近、我附近 | 必选，不提供不限范围 |
| 直线距离 | 1公里、3公里、5公里 | 必选，含边界，无默认档位 |
| 标注人均上限 | 15、30、50、100元以内、不限预算 | 必须主动选择；上限含边界 |
| 最低评分 | 不限评分、3分及以上、3.5分及以上、4分及以上 | 五分制综合口碑分；必须主动选择，门槛含边界 |
| 类别 | 单个启用餐厅类别、不限类别 | 单选，复用现有分类 |
| 用餐方式 | 堂食、外卖、不限 | 必须主动选择 |

候选只包含普通餐厅，食堂和窗口不参与。明确预算时排除人均未知的餐厅；不限预算时可参与。候选必须同时满足全部条件，没有结果时提示用户修改，不自动扩大距离、提高预算或取消其他条件。

评分放在预算之后、类别之前，共六项条件。不限评分允许暂无评分；明确最低分时，暂无评分和低于门槛的店不参与。评分取现有五分制综合口碑分，门槛先于抽样执行；达标店仍等概率，不按分数加权。精度与接口枚举见[API](../api.md#25-帮我选一家候选查询)。

### 抽取、回看与修改

- 在完整合格集合中等概率、不放回抽取，不按评分、评价数量或首页排序加权。
- 同一轮已展示的餐厅不再抽中，不是仅排除上一家。
- 在当前弹窗展示结果，提供查看详情、导航、换一家、上一家。
- “上一家”回看不消耗新候选；回看后按钮显示“下一家”，先沿已有历史前进，到末尾才继续抽新店。
- 全部看完后提示重新抽一轮或修改条件；只有一家明确提示，空候选与本轮已看完区分。
- 修改条件保留已填值，确认后清空历史开启新一轮；取消恢复原条件与结果。
- 主动关闭后重新进入，所有条件重新选择；详情往返属于同一轮，保留条件、当前卡片与历史。
- 历史只保存在会话内存，不写账号、localStorage或数据库；刷新后重新开始。

### 数据与开发约束

- 使用现有数据，不为此功能新建或调整表结构，不增加Flyway迁移。
- 延续排除标注停业、软删除店铺的约束；经营状态不代表实时营业时间。
- 只选可靠位置在所选距离内的餐厅；“我附近”主动定位成功后才能抽取，不以校区或0坐标替代失败定位。
- 堂食/外卖只匹配明确支持，未知不当作满足；不限时未知资料可参与。
- 人均为标注值，距离为球面直线距离，不保证实际结账金额或步行路程，不编造缺失资料。

## 实现与取舍

### 后端候选

选店留在restaurant模块，通过独立请求对象、Controller、应用服务和抽样策略执行。校区中心复用已有服务端配置，目录共享WHERE语义用于普通餐厅、经营状态、预算、类别、用餐方式和距离。

读取完整合格ID集合，在Java中执行部分Fisher–Yates，每批至多5家；只有抽中的店批量补充公开卡片、标签、相册封面及距离。ID、抽样和卡片使用同一只读RR快照。评分门槛直接比较已有生成列，仅作用于独立选店查询，不改变首页/地图查询契约。候选覆盖达标后的完整集合，不依赖ES、Redis会话或外部推荐服务。

选此方案是因为当前校园候选ID规模可控，概率可以明确验证，也不需要前端拉取全部餐厅资料。代价是每次仍扫描合格ID且占用O(N)内存；它不等于大规模下恒定成本，未来数据明显增大再依据测量评估流式蓄水池或其他方案，不直接用随机主键跳转冒充等概率。

请求带本轮已展示/预取ID。复核模式按指定ID检查当前硬条件，保留请求顺序、移除失效项、不补入别的店。每次数据库快照只代表该时点，多次查询间状态可以变化；接口数量不能解释为长期固定总数。精确参数与大小限制由[API](../api.md#25-帮我选一家候选查询)维护。

### 前端状态与详情返回

Pinia独立保存草稿、确认条件、预取队列、已占用ID、展示历史和回看位置，不读取首页catalog。首次抽取后依次使用小批候选，队列用尽再查询下一批；展示预取、回看和详情返回均先复核资料。失效预取跳过且本轮不再抽到，失效历史保留可辨认记录但停止前往。

首次候选失败保留条件并提供重试；补充/复核失败保留已有卡片、队列和历史，不显示为空候选，不推进历史。取消请求配合代次隔离迟到响应，加载时禁用重复操作。

普通详情点击标记`from=picker`并暂挂弹窗；返回原首页历史条目时恢复本轮。直达或无对应历史时安全返回固定首页选店入口；不读取用户任意返回地址。修饰键、新标签页不关闭原弹窗。没有会话快照时展示空白条件表单。

布局采用暖橙色、暖白色弹窗，轻量选项和结果主按钮突出选店操作；手机条件区可内部滚动、底部按钮常驻。无照片或加载失败使用简短占位，评分、人均和距离使用现有公开数据。

## 交付与后续

- 已实现：独立六项条件、全部不预选、最低评分过滤、完整集合均匀抽样、跨批不重复、上一家/下一家、无结果/耗尽/重试、改条件、真实资料/封面、导航与详情返回。
- 验证覆盖：必选与不限区分、校区/用户坐标、距离/预算/用餐方式与未知值、普通餐厅/经营状态、10000条窗口之外候选、并发快照、抽样分支均匀、跨批历史、关窗取消、详情往返及手机/短屏。
- 仍待用户体验验收：真实Android/iOS的定位授权和高德App唤起、实际手感。浏览器模拟尺寸和定位替身不等同于真机GPS验收。
- 未扩展：评分加权、长期个性化、多人决策、服务端抽取会话、新基础设施或表结构。
