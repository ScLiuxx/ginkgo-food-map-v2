# 社区业务规则讨论记录

更新日期：2026-11-07。范围包括“我的”、消息、互动、风控及相关未完成业务。本文集中保存用户逐项确认的未来规则；现有接口与已实现能力分别见[API文档](../api.md)和[功能说明](../features.md)。规则确认不等于功能已经实现。

## 记录方式

- 每次提出一个关键问题，用户回答后更新对应规则，再提出下一项。
- 状态采用“待讨论”“暂定”“已确认”“暂缓”；未回答的问题保持待讨论，不将建议或推荐选项视为用户决定。
- 用户可以补充、自定义、跳过或修改已有决定；修改时直接更新现行条目，确有必要时保留简短变更原因。
- 先明确业务规则，再选择技术和开发顺序；本次访谈不自动启动功能开发。

| LEVEL-013 | 同一人对同一家店多次纠错通过，经验如何奖励？ | 用户明确确认：同一人对同一家店的纠错经验只允许奖励一次；后续仍可正常提交纠错并接受审核，但不再获得该店纠错经验。奖励撤销后保留原资格记录，不因换申请编号重复领奖；自动恢复或补发流程仍未开放。 | 已确认 |

### 简单等级的建议实施顺序

以下是依据已讨论规则整理的开发方向；具体完成状态见[成长实施设计](community-growth-v1.md)，暂定参数仍保留后续调整空间。

1. 经验记录与等级计算：按LEVEL-003/LEVEL-004提供经验增加、对应奖励撤销及等级计算，初始参数引用LEVEL-008/LEVEL-009。
2. 贡献奖励接入：接入已有点评发布与投稿、纠错审核结果；完成最小点评点赞能力，再按LEVEL-006/LEVEL-007/LEVEL-008接入防重复奖励和获赞经验上限。
3. 查询与页面接入：展示数字等级，商户点评列表提供LEVEL-011规定的默认排序与时间排序。
4. 风控联动：将违规或刷分后的对应经验撤销接入已讨论的举报处置流程，维持等级与账号处罚状态分别管理的规则。

具体技术方案、接入位置、完成状态和验收场景见[简单等级与成长奖励一致性设计](community-growth-v1.md)，社区页面接入范围见[前端状态](community-frontend.md)。规则确认不代表所有功能均已实现，产品规则继续以本文件为准。

### 成熟社区等级体系参考

以下为2026-11-06查阅官方资料后的研究与建议；用户已确认的首版等级权益见LEVEL-005/LEVEL-011，未将研究中的其他候选自动纳入开发范围。

- [B站官方FAQ](https://www.bilibili.com/h5/faq)：经验来源包含日常行为，部分奖励设置每日上限，部分异常投币数据不参与经验结算。可借鉴奖励资格与奖励上限的设计；本站已确认的经验来源仍以LEVEL-003为准。
- [Stack Overflow声望说明](https://stackoverflow.com/help/whats-reputation)：核心提问、回答及建议编辑无需声望门槛；声望来自社区认可及有效编辑，部分来源有每日上限，声望增长可解锁更多权限。可借鉴基础贡献开放与逐步开放权益的安排，不照搬其投票撤回后的声望回退规则，本站仍按LEVEL-004处理。
- [Discourse信任等级说明](https://meta.discourse.org/t/discourse-trust-levels-a-detailed-explanation/396792)：默认晋升条件包含阅读、持续参与及来自不同用户的认可，最高信任等级由工作人员人工授予。[官方更新说明](https://blog.discourse.org/2018/06/understanding-discourse-trust-levels/)同时指出，许多功能权限已从固定等级要求迁移为用户组配置。可借鉴成长等级与具体权限授权分别管理的方式。

- [Google商家评分说明](https://support.google.com/business/answer/4801187?hl=zh-Hans)：官方说明商户评分为已发布评分的平均值。[Tabelog评分说明](https://tabelog.com/tw/help/score)则采用用户影响度等因素，结合分类经验及不当行为判断，并说明影响度变化可能使没有新增评价的店铺分数发生变化。成熟平台存在不同计分路径，不能据此直接认定站内成长等级应转换为评分权重。

按用户最新决定，首版等级权益为点评默认排序中点赞数相同时高等级作者优先，另提供按发布时间查看的入口，见LEVEL-005/LEVEL-011；不再采用排序时间加成，等级称号按LEVEL-010暂缓。商户评分继续沿用现有等权规则。默认排序会偏向已累积较多点赞的点评，用户可切换时间排序查看近期体验。若未来采用评分加权，需要单独定义权重依据、反刷分规则，以及升级和降级时历史评分权重的处理方式。操作额度及共建权限均未纳入首版已确认范围。

经验奖励的防重复、同店重复贡献资格及获赞经验上限值得优先明确；经验奖励上限与业务操作次数限制分别讨论，不因限制经验奖励而自动禁止继续发布内容。上述建议均未替代用户决定，也未增加新的独立信用分或自动处罚规则。
