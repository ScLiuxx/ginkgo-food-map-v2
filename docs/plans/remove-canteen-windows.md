# 移除窗口体系，食堂直接点评

2026-11-22用户确认：窗口及现有窗口关联数据永久删除，不把窗口点评迁给食堂。分支`refactor/remove-canteen-windows`，基线`develop@90f6258`。

## 最终规则

- 普通餐厅和食堂统一使用`restaurant_id`发布、读取、互动、删除及计分；食堂可直接点评，无楼层或窗口选择。
- 食堂原有的直接点评保留，每位作者最新有效点评计分，沿用四维、口碑分、首次点评经验和搜索同步规则。
- 管理员直接维护食堂资料；照片沿用正式商户相册，不新增相册维护能力。移除窗口管理、独立详情、相册、点评接口及前端类型。
- 新店附带点评仍只开放普通餐厅，食堂收录后可直接点评。本轮不扩大投稿业务。

## V51清理范围

采用Java Flyway迁移`db.migration.V51__remove_canteen_windows`。V1～V50不改写。MySQL的DDL自动提交，因此先保存持久清理ID集合，事务内删除数据，再逐步拆表/字段；拆结构前检查实际存在状态，失败时保留`_v51_window_*`范围表供核查及修复后重入，成功后删除这些范围表。

| 数据 | 处理 |
| --- | --- |
| 窗口，包括已逻辑删除记录 | 删除全部记录及`canteen_windows`表 |
| 窗口相册、统计 | 删除`canteen_window_photos`、`window_review_statistics`表 |
| 窗口点评、回复、照片关联 | 永久删除；从现存点评、点评回执及WINDOW首次点评奖励共同收集范围 |
| 发布/删除回执 | 删除窗口点评及其全部回复回执，包括正文早已删除的记录 |
| 点赞、举报及正文快照、通知 | 清除窗口点评/回复关联及举报结果通知，保留其他内容 |
| 经验 | 删除窗口来源的首次点评与获赞奖励，仅重算受影响账号剩余有效奖励合计 |
| 媒体对象 | 保留原bucket/key，先持久标记PENDING_DELETE，再删除业务关联；旧WINDOW用途改为通用REVIEW清理登记，禁止重新绑定；保留在途上传及原有保护期限，由清理任务重试物理删除 |
| 食堂统计、搜索 | 仅重建食堂直接点评统计，推进搜索投影版本并登记Outbox；普通餐厅数据保留 |
| 活跃统计 | 历史发布次数表示“当天曾发布”，按已确认口径不回扣；不包含点评正文或窗口ID |

迁移删除`reviews.window_id`、`review_request_receipts.window_id`、对应索引和父食堂组合唯一键，`restaurant_id`恢复非空。媒体新上传只接受REVIEW、RESTAURANT、AVATAR。

## 发布及验收

此迁移不可通过回滚旧JAR撤销，发布前必须备份数据库；需要回退数据时恢复备份，不能只重启旧版本。

1. 停止旧后端写入后备份MySQL，包括Flyway历史和媒体登记；备份保存在访问受限位置，不提交仓库。不要在旧实例仍写入时手工执行清理。
2. 发布新版本，Flyway执行V51。确认迁移成功、三张窗口表与两个window_id字段不存在，且没有`_v51_window_*`遗留表。若失败，停止发布，检查保留范围表和日志；排除原因后再修复迁移历史并重试，禁止盲目repair后运行旧应用。
3. 验证食堂直接发布、同请求重试、同作者再次点评、历史和删除后评分接替，以及普通餐厅、相册、举报及通知。
4. 等待媒体后台清理。保留清理中的登记不表示业务窗口仍存在；只有原对象删除成功且登记被清理后才算云端物理删除完成。不同存储桶需有对应清理权限；不手动先删登记或整个共享图片前缀。
5. 确认食堂Outbox任务成功，ES展示评分与MySQL一致。榜单仍只针对普通餐厅，无需清除普通餐厅榜单快照。
