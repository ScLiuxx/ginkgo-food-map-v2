# 餐厅搜索实现与同步一致性

调用方可见的匹配、分页、`search`元数据与降级语义统一见[搜索接口契约](../api/restaurants.md#search)。本文记录当前引擎选择、保护机制与同步实现，不定义新的HTTP入口。

## 引擎选择

公开列表和地图共用RestaurantQueryService引擎策略；字典及详情始终读取MySQL。ES查询需同时显式开启ES_ENABLED及ES_QUERY_ENABLED，默认不启用。列表无关键词浏览及单汉字搜索均优先走ES；地理条件缺原点时走SQL。地图点位无关键词仍走SQL。口碑分/热度/价格/点评数/有原点距离排序及默认相关度均可走ES；未知价格和距离排后。

## 分析、熔断与地理计算

- 查询与建索引分别使用ik_smart和ik_max_word；完整店名以独立排序层处理，匹配与排序语义见接口契约。
- ES查询接入Resilience4j进程内熔断，列表/地图共享：统计最近20次调用，至少10次后失败率达到50%打开，等待10秒后由首个符合ES入口条件的真实请求触发半开，只允许1次探测，其余直接走SQL；探测成功关闭、失败重新等待10秒。只包ES字段检查/分析/搜索，不把SQL回查或降级成功算ES成功，也不将同步积压或资料变化计为ES故障。空结果仍是成功。半开及熔断状态随进程重启清空，不跨实例共享。
- 不新增后台探活、查询自动重试或全量恢复工具；独立慢调用比例熔断本轮不启用。ES执行超时800ms、客户端连接2s；单次HTTP调用同时设置socket与请求级响应超时3s，防止连接已建立但服务不响应时无限等待。这不是整个多阶段ES流程或接口总时限，熔断不会取消已在执行的请求，SQL降级另需时间。
- 地理runtime字段从_source原始GCJ-02坐标计算，视口含边界，距离沿用SQL的6371000米半径和haversine公式；不使用geo_point量化坐标或不同地球半径改变既有规则。该方式有读取原文与计算成本，尚未做性能收益评测。

## 写入与异步同步

商户新建、编辑、删除、审核通过及点评统计更新，在原业务事务内保存搜索Outbox；任务写入失败时业务整体回滚。待审申请、驳回、回复和幂等重试不重复生成任务。接口成功只表示MySQL资料和任务已提交，不保证ES立即可见。消费者是否运行由部署开关控制，失败任务延迟重试，达到上限保留FAILED，不提供HTTP失败重放入口。

影响搜索内容的成功事务提交后立即通知异步Outbox消费者，空闲唤醒后固定200毫秒合并窗口，30秒定时扫描兜底；批内同餐厅合并后通过Bulk写入，逐项确认本批捕获任务。HTTP不等待ES完成，搜索仍为最终一致性，不保证提交即刻可见；无接口参数或响应变更。调度与指标口径见[同步说明](../operations/elasticsearch-sync-metrics.md)。

表字段见[Outbox表结构](mysql-schema.md#restaurant-search-outbox)，索引投影见[ES结构](elasticsearch-schema.md)，运行开关、唤醒和指标见[同步运维说明](../operations/elasticsearch-sync-metrics.md)。
