# 餐厅搜索实现与同步一致性

调用方可见的匹配、分页、`search`元数据与降级语义统一见[搜索接口契约](../api/restaurants.md#search)。本文记录当前引擎选择、保护机制与同步实现，不定义新的HTTP入口。

## 引擎与读取路径

公开列表和地图共用RestaurantQueryService引擎策略；字典及详情始终读取MySQL。ES查询需同时显式开启ES_ENABLED及ES_QUERY_ENABLED，默认不启用。列表无关键词浏览及单汉字搜索均优先走ES；地理条件缺原点时走SQL。地图点位无关键词仍走SQL。口碑分/热度/价格/点评数/有原点距离排序及默认相关度均可走ES；未知价格和距离排后。

列表直接消费ES公开投影，不再回查MySQL或Outbox判断资料是否最新，因此资料、评分和删除状态允许同步延迟。封面关联ID只用于生成本站图片地址，图片读取仍校验业务可见性；四维及审计时间未进入投影，列表不临时补查。地图点位保留身份与版本回查，不把列表当前页当作完整地图结果。

ES调用失败或熔断拒绝时，整个请求使用SQL降级；ES成功返回空结果不触发降级。地图回查发现投影不一致时也整次降级，不混合不同来源的分页、总数和排序。索引字段及保留的历史映射见[ES结构](elasticsearch-schema.md)。

## 分析、熔断与地理计算

- 查询与建索引分别使用ik_smart和ik_max_word；完整店名以独立排序层处理，匹配与排序语义见接口契约。
- ES查询接入Resilience4j进程内熔断，列表／地图共享。失败达到阈值后打开，等待后由符合ES入口条件的真实请求触发半开，只允许有限探测；探测成功关闭，失败重新等待。只包ES字段检查／分析／搜索，不把SQL降级成功算ES成功，也不把同步积压或地图回查发现资料变化计为ES故障。空结果仍是成功，状态不跨进程共享。
- 查询没有独立后台探活或自动重试，慢调用比例不作为单独熔断条件。ES执行、客户端连接、socket及响应均设超时；单次请求超时不等于整个多阶段查询及SQL降级的总时限，熔断不会取消已在执行的请求。阈值和默认超时以[应用配置](../../backend/src/main/resources/application.yml)为准，故障验证见[演练记录](../history/elasticsearch-metrics-fault-drill-2026-11-10.md)。
- 地理runtime字段从_source原始GCJ-02坐标计算，视口含边界，距离沿用SQL的6371000米半径和haversine公式；不使用geo_point量化坐标或不同地球半径改变既有规则。该方式有读取原文与计算成本，尚未做性能收益评测。

## 写入与异步同步

商户新建、编辑、删除、审核通过及点评统计更新，在原业务事务内保存搜索Outbox；任务写入失败时业务整体回滚。待审申请、驳回、回复和幂等重试不重复生成任务。接口成功只表示MySQL资料和任务已提交，不保证ES立即可见。消费者是否运行由部署开关控制，失败任务延迟重试，达到上限保留FAILED，不提供HTTP失败重放入口。

成功事务提交后的进程内事件只用于唤醒消费者，Outbox才是可恢复的任务依据。消费者有界合并同餐厅任务，通过Bulk逐项确认本批捕获的任务；定时扫描补偿通知丢失、重启及到期重试，不顺带确认消费期间新生成的任务。投影版本和删除墓碑阻止旧任务覆盖新状态。HTTP不等待ES完成，搜索保持最终一致性。

表字段见[Outbox表结构](mysql-schema.md#restaurant-search-outbox)。唤醒窗口、扫描间隔、Bulk批次限制、重试与指标参数集中见[同步运维说明](../operations/elasticsearch-sync-metrics.md)，不在本文维护第二份参数清单。
